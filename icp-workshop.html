How these metrics are calculated

For scan i, position error is eᵢ = ||t_estimated,i − t_true,i||₂ using all three XYZ coordinates. Trajectory position RMSE is sqrt(mean(eᵢ²)) over all currently computed poses, including the origin. The path plot shows XY only; vertical drift still contributes to the error plot.

Rotation error is the angle of R_true.T @ R_estimated: acos(clip((trace(R_true.T @ R_estimated) − 1) / 2, −1, 1)), converted to degrees. It measures the full 3D rotation, not only heading. These errors use known synthetic poses; the pairwise NN RMSE beside the editor measures scan alignment and is a different quantity.

The function contract

Mind the coordinate frames

source: (N, 3) and target: (M, 3) are NumPy arrays in metres. +X is forward, +Y left, +Z up. Point order is shuffled: matching indices are not matching points.

p_previous = R @ p_current + t
T_map_current = T_map_previous @ T

For row-wise NumPy points:

aligned = source @ T[:3, :3].T + T[:3, 3]

The bottom row is [0, 0, 0, 1]. Rotation must be orthonormal with determinant +1. Scan 01 is the map frame.

Hints for point-to-point ICP
  1. Start with T = np.eye(4) and transform the source.
  2. Find nearest neighbours in the target; reject matches farther than 0.5 m. Keep at least three non-collinear pairs.
  3. Subtract both centroids and form H = A.T @ B.
  4. Compute U, S, Vt = np.linalg.svd(H), then R = Vt.T @ U.T. Correct a negative determinant by flipping the last row of Vt.
  5. Use t = centroid_B - R @ centroid_A. Put R and t in an identity matrix delta.
  6. Update T = delta @ T. Stop when the error change is small or after at most 60 iterations.
Build it step by step

How to implement registration(source, target)

Download the worked example

Your task is to estimate how one scan must move to overlap the previous scan. The two clouds observe the same static environment, but the robot moved between measurements. Iterative Closest Point (ICP) alternates between guessing which points correspond and solving the rigid transformation of those pairs. Start with the runnable identity baseline, add each step below, then compare the resulting trajectory with ground truth.

1. Inputs & output2. Transform3. Match4. Filter5. Solve R and t6. Compose7. Stop8. Map & debug

1. Understand exactly what goes in and what comes out

source is the current scan: an (N, 3) NumPy array. target is the previous scan: an (M, 3) array. Each row contains [x, y, z] in metres, relative to that scan’s own sensor. The numbers of points can differ. Dropout, occlusion and shuffled ordering mean that source[k] and target[k] generally describe different surfaces.

Return one matrix T_previous_current of shape (4, 4). It converts current-sensor coordinates into previous-sensor coordinates:

T = [[R00, R01, R02, tx],
     [R10, R11, R12, ty],
     [R20, R21, R22, tz],
     [  0,   0,   0,  1]]

R is a 3 × 3 rotation and t a 3-vector. For example, if the robot moves 0.16 m along +X without rotating, a stationary object appears 0.16 m closer in the new sensor frame. The current-to-previous transform therefore has tx = +0.16, not −0.16.

The runner handles file loading and order. It initializes scan 01 at identity, then calls your function 99 times: scan 02 → 01, scan 03 → 02, …, scan 100 → 99. The page numbers scans 01–100; the corresponding CSV filenames are scan_00.csv through scan_99.csv. Your function solves one pair; do not load files, traverse all scans, or return the whole trajectory inside it. Ground truth is for evaluation only and is not passed to your function.

2. Start from identity and transform the source

Initialize T = np.eye(4). Identity is a reasonable first guess here because neighbouring scans have small motion and substantial overlap. With large motion, ICP may converge to a wrong local solution; running more iterations cannot always fix a bad initial guess.

T = np.eye(4)
previous_error = float("inf")
for iteration in range(60):
    moved = source @ T[:3, :3].T + T[:3, 3]

The mathematical convention is p_previous = R @ p_current + t for column vectors. NumPy stores our points as rows, so use source @ R.T + t. Translation broadcasts over all rows. Always recompute moved from the original source and the accumulated T; repeatedly applying T to an already transformed source would apply old corrections twice.

3. Find nearest-neighbour correspondences

For each point in moved, find the target point with the smallest Euclidean distance. Squared distances give the same nearest neighbour and avoid unnecessary square roots. The small-batch implementation below is the one used in the sample:

indices = np.empty(len(source), dtype=int)
squared_errors = np.empty(len(source))
for start in range(0, len(source), 128):
    batch = moved[start:start + 128]
    distances = ((batch[:, None, :] - target[None, :, :]) ** 2).sum(axis=2)
    nearest = distances.argmin(axis=1)
    indices[start:start + len(batch)] = nearest
    squared_errors[start:start + len(batch)] = distances[np.arange(len(batch)), nearest]

distances has shape (batch_size, M); each row compares one source point with every target point. argmin(axis=1) gives the target index for each source point. This brute-force search costs O(NM) work per iteration. Batching limits temporary memory; it does not change the matches. A spatial index such as a KD-tree is an extension for larger clouds, but this workshop’s sample only needs NumPy.

Recompute correspondences after every transform update. Matching once and solving once is a rigid least-squares fit of guessed pairs, not the full ICP loop.

4. Reject implausible pairs

A newly visible wall may have no counterpart in the previous scan. Do not force every return into a correspondence. Start with a 0.5 m distance gate:

keep = squared_errors < 0.5 ** 2
if keep.sum() < 3:
    raise ValueError("Too few matches within 0.5 m")
a = moved[keep]
b = target[indices[keep]]

The comparison is with 0.5 ** 2 because the stored errors are squared. a and b now have the same shape and corresponding rows. Use at least three non-collinear pairs. A tiny gate can remove the pairs needed to recover motion; an overly large gate can accept points on unrelated surfaces. Inspect the map and error curves when changing it.

5. Solve the incremental rotation and translation with SVD

For the fixed pairs, minimize Σ ||R @ aᵢ + t − bᵢ||². First subtract each set’s centroid. This separates the rotation problem from translation:

centroid_a = a.mean(axis=0)
centroid_b = b.mean(axis=0)
A = a - centroid_a
B = b - centroid_b
H = A.T @ B
U, singular_values, Vt = np.linalg.svd(H)

H is 3 × 3. NumPy returns Vt, the transpose of V. With this definition of H, the source-to-target rotation is Vt.T @ U.T. A reflection can also minimize the unconstrained fit, so enforce a proper rotation with determinant +1:

if singular_values[1] < 1e-10:
    raise ValueError("Collinear or coincident matches")
if np.linalg.det(Vt.T @ U.T) < 0:
    Vt[-1] *= -1
R = Vt.T @ U.T
t = centroid_b - R @ centroid_a

The second singular value checks whether the matched geometry has collapsed to a line or point. Planar but non-collinear points can still provide a rigid fit; do not reject all planar data just because the third singular value is small. Translation moves the rotated source centroid onto the target centroid.

6. Compose the correction in the right order

This R and t align the already transformed points in moved to the target. They form an incremental correction called delta, not the complete source-to-target estimate:

delta = np.eye(4)
delta[:3, :3] = R
delta[:3, 3] = t
T = delta @ T

Read this right to left: first apply the existing T to the original source, then apply delta. Overwriting T = delta discards earlier iterations. Using T @ delta applies the correction in a different frame. Adding translations separately also fails once rotation is present.

7. Check convergence and return the accumulated matrix

Measure the mean squared distance of the retained nearest-neighbour pairs on each iteration. The sample stops when the change between consecutive iterations falls below 1e-9 m², or after 60 iterations:

error = squared_errors[keep].mean()
if abs(previous_error - error) < 1e-9:
    break
previous_error = error

# Outside the iteration loop:
return T

A small change means the optimizer has stopped moving much; it does not guarantee the correct pose. The page checks that the returned matrix is finite, has bottom row [0, 0, 0, 1], and contains an orthonormal rotation with determinant +1. Those checks verify the matrix format, while ground-truth plots assess accuracy.

The sample’s stopping error uses only retained pairs. The page’s pairwise NN RMSE uses all current-source points after the returned transform. They can differ, especially where occlusion creates unmatched surfaces.

8. Follow the runner from pairwise transforms to a map

The runner multiplies your current-to-previous estimate by the previous global pose. This multiplication is different from the incremental correction inside ICP:

# Runner logic; you do not need to put this inside registration().
T_map_current = T_map_previous @ T_previous_current
points_in_map = source @ T_map_current[:3, :3].T + T_map_current[:3, 3]
robot_position = T_map_current[:3, 3]

Each small pose error affects later scans. Over this roughly 20 m route, even a modest rotation error can produce noticeable translation drift and doubled walls. The sample performs scan-to-scan registration; it has no loop closure or global map optimization. Use the ground-truth overlay to see this accumulation.

For a quick self-test, make a random non-degenerate target cloud, choose a small known R and t, and construct source = (target - t) @ R. Shuffle the source. Your function should recover the chosen transformation. Then run all 100 workshop scans in sequence (99 calls), inspect the trajectory plot, and compare the selected position error with the overall position RMSE.

Take the lab with you

Three connected bays. 100 viewpoints.

A reproducible, synthetic indoor sequence in a 24 × 16 m lab with two partitions, wide doorways, workbenches, cabinets and pillars. The 100-scan route travels about 20 m through all three bays, with an S-shaped path, left and right turns, and a final north-facing pose. A 360° LiDAR samples four elevation rings, with occlusion, a 12 m range limit, dropped returns and 6 mm range noise. The robot follows the path tangent, with headings from about −50° to +90°. Scans are closer together around bends to keep successive rotations below 5° and preserve overlap.

Work locally: unzip the kit, install NumPy, finish registration.py, and run python registration.py. For a worked example, run python sample_solution.py. Import the resulting transformations.json here to see your map.
