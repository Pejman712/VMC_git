Project 01 · 2022

Autonomous Rescue Robot

A robot for rescue missions that maps its surroundings and threads through small openings — navigating autonomously using only a 3D LiDAR.

Platform Differential-drive robot Sensor Velodyne VLP-16 3D LiDAR Control Arduino Micro & Nano Stack ROS Navigation Team Alamikkotervo · Habibiroudkenar · Rumjantsev · Vainio
1 Challenges

Squeeze through, safely

  • Build a robot genuinely useful in rescue missions — able to map an unknown space and pass through narrow openings.
  • Navigate autonomously using a 3D LiDAR as the only exteroceptive sensor, with no dedicated 2D scanner.
  • Handle extremely tight clearances, with obstacles just centimetres from the wheels.
  • Quantify how accurate the resulting navigation actually is.
2 Methods

Platform & navigation

  • Modified a differential wheeled robot to support autonomous navigation.
  • Mounted a Velodyne VLP-16 3D LiDAR as the sole perception sensor.
  • Arduino Micro and Nano for low-level motor and sensor control.
  • Ran the ROS Navigation Stack, localising from wheel odometry fused with 3D LiDAR data.
  • Built both 3D and 2D maps of the environment on the fly.
3 Results

4 cm to spare

  • With optimal localisation, the robot passed through a gap with only 4 cm clearance between the wheels and the obstacles.
  • Produced an accurate 3D and 2D map of the environment.
  • Wheel odometry + 3D LiDAR alone were not accurate enough for consistent localisation.
  • Recommendation: add an IMU as a second localisation sensor for more reliable results.

Project 02 · Mira robot · CERN

Comparison of Path-Finding Algorithms

Benchmarking A*, Dijkstra and RRT for autonomous navigation of mobile robots, to replace manual control of CERN's radiation-survey robots.

Goal Autonomy for the Mira robot Stack ROS · Gmapping SLAM · Python Test bed Gazebo sim + Dbot (Aalto) Metrics Path length · compute time · nodes Authors Harju · Anis · Salo · Hussain · Habibiroudkenar · Kuosmanen · Kiviluoma
1 Challenges

Which planner, and why

  • CERN's radiation-survey robots are manually controlled — slow, demanding, and human-intensive.
  • Automating navigation means picking a path planner that balances path length, computation time, node count and power.
  • No single algorithm wins everywhere — the right choice is application-dependent.
  • Test in a genuinely hard map: three CERN facility grids with over 50% of cells occupied.
2 Methods

Build, map, benchmark

  • Built on ROS (rviz, rclpy, nav_msgs); Gmapping SLAM for 2D occupancy grids.
  • Implemented A*, Dijkstra and RRT in Python, with a Euclidean-distance heuristic on an 8-connected grid.
  • Tested on three 629 × 810 facility maps, each algorithm run 30+ times with varied start/goal pairs.
  • Validated in a Gazebo simulation, then on Dbot — a real LiDAR-equipped robot at Aalto.
3 Results

A* is the balance

  • A* gave the best overall balance — near-optimal paths at low compute cost.
  • Dijkstra matched A*'s path length but was 2×+ slower, exploring uniformly in all directions.
  • RRT explored the fewest nodes but produced longer, sub-optimal paths at far higher compute time.

Project 03 · 2026

Overcoming LiDAR Blind Spots with M2M Communication

A cooperative-perception layer that bridges a ceiling-mounted crane LiDAR to an autonomous mobile robot, giving it active human detection in its near-field blind zone.

Setup AMR (16-ch) + crane LiDAR (32-ch @ 2.95 m) Link 5 GHz Wi-Fi · ROS 2 Humble Model VoxelNeXt human detection Stack tf2 · Nav2 occupancy grid Team Precision 5 — Eid · Le · Ijaz · Tervonen · Long
1 Challenges

The near-field blind zone

  • AMRs increasingly rely on 3D LiDAR in dynamic, human-shared indoor spaces.
  • Every 3D LiDAR has a physical minimum detection range, creating a ~70 cm blind zone that risks collisions with nearby people.
  • Add a real-time, safety-oriented perception layer for active human detection.
  • Do it without physically modifying the vehicle itself.
2 Methods

Cooperative perception

  • Paired a differential-drive AMR (16-channel LiDAR) with an overhead crane LiDAR (32-channel at 2.95 m).
  • Machine-to-Machine (M2M) link over local 5 GHz Wi-Fi via ROS 2 Humble.
  • Pipeline: dynamic coordinate alignment with tf2 → human detection on crane data with VoxelNeXt → merged point cloud → 2D occupancy grid for Nav2.
  • Switched DDS QoS from Reliable → Best Effort to remove network latency and system freezing.
3 Results

Blind zone eliminated

  • Eliminated the 70 cm blind zone — the AMR autonomously halted for occluded near-field humans.
  • Latency stayed low enough to trigger safety stops before collision.
  • VoxelNeXt accuracy rose from 10–50% in static scenes to an 85% peak in dynamic ones, as motion exposed varied scan angles.
  • Limits: scaling to large warehouses may add transmission delay; 1 Hz logging likely under-reported true responsiveness.

Project 04 · SMEAK / Panther UGV

From Satellite Imagery to Full-Stack Outdoor Navigation

An outdoor autonomy stack that drives a UGV ~250 m between two points clicked on a satellite image — staying on the road, stopping for people, avoiding obstacles, with no premade map.

Platform Husarion Panther V1.2 (skid-steer) Sensing StereoLabs ZED X · Orin NX · GNSS/IMU Stack ROS 2 · Nav2 · OSMnx · PPLiteSeg Mission ~250 m outdoor A → B → A Author Habibiroudkenar
1 Challenges

Autonomy from a map click

  • Drive outdoors from a point clicked on satellite imagery to another, with no premade map to save memory and stay flexible.
  • Extract a drivable road network from overhead imagery.
  • Convert a GPS route into the robot's local frame so Nav2 can follow it.
  • Perceive the drivable surface locally with a camera, and stop for people.
  • Fuse the global GPS route with local perception, then survive the sim-to-real gap.
2 Methods

A five-stage stack

  • Simulation: a Gazebo/Ignition digital twin over a Husarnet VPN as the test workbench.
  • Road extraction: PCA feature maps and SAM were only partial; OSM + parameter-tuned extraction produced a clean, connected road graph.
  • Route planning: click GPS start/goal in Mapviz → OSMnx graph + networkx shortest path on real roads.
  • Hand-off: GPS → map frame via UTM-anchor or /fromLL → densified waypoints → sequential Nav2 NavigateToPose.
  • Perception: classical → FastSAM → adopted PPLiteSeg semantic segmentation (road + person), feeding a fusion node and a human safety stop.
3 Results

Components proven in sim

  • Learned satellite segmentation alone failed to isolate roads; OSM + tuning gave a clean, plannable network.
  • The GPS → Nav2 pipeline was validated in sim — a coherent global route with smooth, obstacle-avoiding local paths.
  • PPLiteSeg gave the most stable drivable-surface segmentation and enabled a working human emergency stop.
  • Each component works standalone; full end-to-end fusion on the real vehicle was the remaining next step, blocked by frame, latency and DDS sim-to-real issues.
